# Contributing to posi-data

This repo is the canonical, versioned data source behind POSI. Most changes
belong in one of two categories.

## Proposing a PSC taxonomy change

1. Open a PR editing `taxonomy/psc/v{X}.{Y}.json` (bump the version — never
   edit a released version file in place).
2. Include the evidence the change is based on: journal scope statements,
   article topic distribution, or citation network data. See
   `PJR-SPEC.md § 10` for what a Subject Editor needs to review the change.
3. If accepted, `taxonomy/psc/current.json` is updated in the same PR.

## Proposing a journal classification change

Publishers and editors may open a PR against a specific journal record in
`journals/core/<shard>/<journal_id>.json` proposing a different `primary` or
`secondary` PSC classification. Include the same evidence as above. Accepted
or rejected, the discussion stays attached to the PR — POSI does not make
silent reclassification decisions.

## Reporting a data error

Open an issue with the `journal_id` (or ISSN) and what's wrong. For
citation-integrity concerns (self-citation, citation stacking, suspected
citation cartels), see `PJR-SPEC.md § 9` and use the `citation-integrity`
issue label — these are triaged separately from ordinary metadata
corrections.

## What this repo does *not* accept PRs for

- Manual edits to `metrics/` or `rankings/` — these are generated by
  [posi-engine](https://github.com/WENSHAO521/posi-engine) and are only ever
  updated by its release workflow.
- Edits to a `manifests/PJR-*.json` file after it has been referenced by a
  published GitHub Release — publish a correction release instead
  (`PJR-SPEC.md § 7`).
